# Performance and limits (measured)

Generated by `python scripts/benchmark.py` on **Linux-6.18.44-fc-v185-x86_64-with-glibc2.39**, 4 vCPU, Python 3.13.17.
Configuration: hash embedder, local vector store, SQLite, no LLM (so no network latency from embedding or LLM providers is included – a real provider adds its own latency and cost).
Numbers are for this sandbox; run the script on your hardware before sizing a deployment. Raw data: [`perf.json`](perf.json).

## 1,000-page PDF (0.96 MB, synthetic text, 5,000 chunks)

| Measure | Result |
|---|---|
| Ingestion (extract + chunk + embed + commit) | **5.6 s** (177.3 pages/s) |
| Peak process memory (whole benchmark incl. the CSV below) | 705 MB (PDF stage alone: 274 MB) |
| Exact search for a name across all pages | **106 ms** (max 121 ms) · count **25** = expected **25** |
| Hybrid retrieval (BM25 + vectors, rerank, parent expansion, grading) | p50 19 ms · p95 161 ms (p95 includes the one-off index load) |
| Complete `/ask` (routing, retrieval, extractive answer, verification, citation check) | p50 **86 ms** · p95 98 ms |
| Summary report from the whole document (short style) | build 1.6 s · render PDF 0.14 s / DOCX 0.06 s / XLSX 0.08 s |

## 200,000-row CSV (6.1 MB)

| Measure | Result |
|---|---|
| Ingestion (parse + text rows + embed + commit) | 18.2 s (10,992 rows/s) |
| Load into typed pandas tables | 2929 ms first time · **1.2 ms** from the per-file cache afterwards |
| Profile (types, missing, stats, duplicates) | 1255 ms |
| Monthly trend with year-over-year | 1285 ms |
| Outlier detection (IQR) | 10 ms |
| SQL sandbox: build in-memory SQLite / `GROUP BY` query | 1654 ms / 65 ms |
| Natural-language question ("Which region has the highest total revenue?") | 208 ms |

## Design limits and what happens at them

| Limit | Value | Behaviour |
|---|---|---|
| Upload size | `MKA_MAX_UPLOAD_MB` = 50 | 413, nothing stored |
| PDF pages | `MKA_MAX_PDF_PAGES` = 5000 (tested to 1,000) | clear refusal above the limit |
| Font-size heading detection | PDFs ≤ 400 pages | larger PDFs use bookmarks only (cost control) |
| Table detection in PDFs | only pages with ≥ 6 vector drawings (ruled tables) | borderless tables are not detected; the text is still searchable |
| Sentence diff (comparison) | 20,000 sentences per document | result flagged `truncated` |
| Contradiction scan | 3,000 sentences per document, candidates by shared words | heuristic candidates unless an LLM confirms |
| SQL sandbox | one SELECT, 3 s, 200 rows per call (max 2,000) | 422 with the reason |
| Parsed spreadsheet cache | 6 files / 3 M cells | evicted LRU, invalidated when the file changes |
| Reports | `MKA_REPORT_MAX_MB` = 25; PDF tables cap at 500 rows | 413 / note in the document |
| Agent node | `MKA_NODE_TIMEOUT_S` = 120 | honest "did not finish" answer; the worker thread cannot be killed, it finishes in the background |
| Memory notes | 50 per user, 300 characters | 422 |
| Embedding with the offline hash embedder | lexical only | paraphrases are missed (listed in the evaluation report) |

Findings from this benchmark that changed the code: an uncached citation check made `/ask` on this document 476 ms instead of 86 ms (the check now tokenises only the cited units); re-parsing a large spreadsheet for every analytics call cost seconds (now cached per file).
